# 987：正在进行记录的跨设备实时活动同步

## 目标与边界

完整时间记录继续保存在用户的 iCloud。服务器只接收切换事件、短期事件队列、设备的 ActivityKit push token 和鉴权信息；不存整份时间记录。

每次成功切换生成独立 `eventID`、`sourceDeviceID`、单设备递增 `sourceSequence`、旧记录 ID、新 Ongoing 记录 ID、类别、开始时间和提交时间。即使一分钟内连续切换多次，也逐条入本地持久化 outbox。V173 的分钟精度可能使同一分钟的中间记录在最终时间链中变成零时长或被覆盖；事件队列仍保存每次成功点击。不能承诺 APNs 逐次显示所有中间状态，手机实时活动最终显示最新状态。

## 传输

1. 手机以 ActivityKit `.token` 创建实时活动，监听 token 更新，并向服务器登记 token。活动不存在时，按系统能力重新创建或使用 push-to-start。
2. Mac 或手机切换成功后，本地先保存事件；发送失败则保留并按原顺序重试。服务端按 `eventID` 去重，按设备序号检查缺口，不覆盖未处理事件。
3. 服务端为每个账户分配全局序号，将事件持久化到有限期限的队列；对该账户其他设备的实时活动发 APNs 更新。APNs payload 带当前类别、开始时间和单调递增的更新 `timestamp`。服务器必须把 Unix 时间转换为 Swift `Date` 默认 JSON 表示所用的 Apple 参考时间。
4. 手机启动、回到前台或 iCloud 文件到达时，核对队列和 iCloud 时间链。完整记录仍以 iCloud 文件为持久来源；若云文件尚未到达，实时活动先显示推送状态，不把仅有的推送消息当作完整历史。
5. 连续点击可有多个事件，但不对每秒计时发推送。APNs 允许限流、延迟或丢包，因此必须保留重试与前台核对。

## 服务器沙盒

TimeTracker 的服务进程、配置、数据库和 APNs `.p8` 私钥放在专属目录中。进程只读写该目录；私钥只在服务端，不进 App、Git 或日志。数据库只保留所需的 token、最新状态、短期事件及确认游标，并设置到期清理。服务端鉴别账户和设备后才接受登记或切换事件；一个账户只能推送自己的设备。

## 当前实现进度

已实现本地 `TransitionOutbox`：事件逐条持久化、重启恢复、按 ID 确认；首页成功切换会入队。服务器接口、鉴权、token 登记和 APNs 发送尚需按服务器的实际部署环境接入。在这些部分完成前，本地队列不会让另一台设备收到更新。
