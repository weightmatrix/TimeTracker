# TimeTracker 开发手册

## 产品范围

TimeTracker（显示名称：李知本·时间）保留计时、时间记录、效率统计、勋章目标、系统提醒事项、日历、番茄钟和口算。iOS、macOS 共用主应用源码；小组件和 Live Activity 使用独立目标。

授课、档案以及档案中的表格清单已从应用源码移除。用户原有的 iCloud 文件、旧备份和 Git 历史不自动删除。

## 主要代码

- `TimeTracker/TimeTrackerApp.swift`：主应用、页面、`TimeStore`、`EfficiencyStore`、`TaskStore`、`CalendarStore`、`CloudSyncManager`、`CloudFileManager`、备份管理。
- `TimeTracker/RecordMutationEngine.swift`：V173 时间记录的覆盖、磁吸、截断、跨日和首页切换；`Tests/V173MutationTests.swift` 覆盖主要边界。
- `TimeTracker/UbiquityContainerProvider.swift`：iCloud 容器定位和身份变化处理。
- `TimeTracker/DebugLogCenter.swift`、`TimeTracker/TelemetryEvents.swift`：诊断日志与遥测。
- `TimeTrackerWidget/`：小组件与 Live Activity 相关代码。

## 数据与同步

- 时间记录：iCloud 容器 `iCloud.com.Han.TimeTracker` 的 `Documents/记录/timeRecords_v20.json`。
- 效率：同目录下的 `efficiency_data_final_v20.json`、`weekly_targets_v20.json`、`efficiency_settings_v20.json`。
- 设置：`Documents/设置/sub_categories_config.json`、`global_settings.json`。
- `CloudSyncManager` 只监听以上六个活跃文件。`CloudFileManager` 维护 iCloud 文件与本地镜像；`TimeStore` 收到记录文件变更后重载。
- 系统提醒事项和日历通过 EventKit 访问，不使用旧档案表格清单。

完整记录仍由 iCloud 同步，跨设备到达时间没有应用级确认。#987 增加独立 APNs 中继，只发送成功切换的短期事件和实时活动状态，不存整份记录。客户端本地 outbox 按序重试，服务端按设备序号和事件 ID 去重；配对、部署及限制见 `手册/987-APNs同步方案.md`。不能把推送送达当作 iCloud 文件已同步。

## 备份

- 应用转入后台或非活跃状态时，将计时、效率和设置编码为 JSON，存入本地 `LocalBackups/SystemSnapshots`。
- 时间记录、效率和设置在保存时还各自生成历史备份。
- 数据管理页可读取新的 JSON 自动快照和旧版整目录快照。旧版快照只为兼容历史恢复保留；新备份不再复制档案、教案目录。

## 编译检查

```sh
xcodebuild -project TimeTracker.xcodeproj -scheme TimeTracker -configuration Debug -destination 'platform=macOS,arch=arm64' build CODE_SIGNING_ALLOWED=NO
xcodebuild -project TimeTracker.xcodeproj -scheme TimeTracker -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
```

源码位于 Git 仓库，`main` 推送到 `https://github.com/weightmatrix/TimeTracker.git`。

## V173 记录规则与回退

- 记录编辑作为新 ID 的 A 插入；旧记录 B 留在处理队列中，依覆盖、截断与合并规则处理。类别只看 `Category`。
- 首页切换用同一个取整到分钟的时刻结束旧 Ongoing、开始新 Ongoing；同类别点击无效。
- 输入和结果不得含实际未来时间；Ongoing 的 `distantFuture` 仅为结束标记。跨日切割只处理已过去的午夜，最后一段保持 Ongoing。
- 相邻记录拖动在一个保存事务内完成两侧修改。旧数据中本已存在的空档保持原样，新增空档或重叠会拒绝并保留原记录。
- 大改前的 Git 分支 `backup/v173-before-algorithm-rework-20261111` 与标签 `backup-v173-before-algorithm-rework-20261111` 均指向 `55e37e1a07dacd454d3b10b2ac2924fc2711565b`。需回退时，从该标签恢复代码；不要用 Git 操作覆盖用户的 iCloud 数据。
